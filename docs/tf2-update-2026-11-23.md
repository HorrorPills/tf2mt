## 1. DirectX 8
* tf2mt sets no DX level anywhere (no `-dxlevel`, no `mat_dxlevel`). mastercomfig-base.vpk has a `dxsupport` table with entries 80–100, but they only
  hold per-level defaults; it selects no level. Source picks 95 from
  the adapter identity (docs/decisions/ADR-001). The owner's saved level: `DXLevel_V1` = 0x5f (95).
* New in `scripts/tf2.sh`: `-dxlevel`/`+mat_dxlevel` below 90 in the launch options becomes `-dxlevel 95`. A saved
  `DXLevel_V1` below 90 adds `-dxlevel 95` once (TF2 saves it). Each change goes to `~/Games/tf2/logs/migrations.log`.
  Unit-tested with bash 3.2 (10 cases: spaces in args, 98 kept, the player's own 90 kept, no registry, no args).
* Renderer (`src/frontend/device.c`, `src/unixlib/render.mm`, `resources.mm`): 16- and 32-bit index buffers,
  `DISCARD`/`NOOVERWRITE` locks (rename on discard), and any index order are supported. The only fixed-function path is the
  pixel stage for VS-without-PS draws (depth passes), which DX9 meshes use too. No FVF or DX8 vertex formats are used
  (`SetFVF` is a no-op). After the update: the same renderer log warnings as before
  (1 kind), no new skipped-draw reasons.

## 2. Rubikon
* `vphysics_rubikon.dll` imports only `tier0.dll`, `KERNEL32.dll`, `RPCRT4.dll` (`UuidCreate`, `UuidFromStringA`).
  Wine 10's builtins cover them: no `WINEDLLOVERRIDES` change needed.
* Live test (local listen server, `koth_harvest_final`, Metal and DXVK): `-rubikon` → 58 `vrn*` cvars; 6
  `prop_physics` spawned, `explode` ragdoll, gravity changes: game stable. Without the flag: 0 `vrn*` cvars.
  The game prints: "sv_wallbugs ... MUST be enabled for player movement to work correctly with VPhysics Rubikon"
  (Valve's warning, not a Wine issue).
* End-to-end through `scripts/tf2.sh` (`TF2_RUBIKON=1`, no direct flag, Metal): 58 `vrn*` cvars; screenshots show the
  stacked barrels, then the explosion knocking a barrel over with gibs on the floor (logs/mousefps/rbk2-metal).
* Launcher: Debug tab → "Experimental Rubikon Physics (-rubikon)", off by default → `TF2_RUBIKON=1` → tf2.sh adds
  `-rubikon` (not twice).

## 3. Patches and caches
* tf2mt writes to no game binary: no pattern scans, offsets, or memory patches. The mouse fixes act on Wine
  (`tools/wine-patches/winemac_warp_nodiscard.sh` patches `winemac.so`; `relmouse` swizzles Wine's ObjC classes). The
  Friends stall fix uses `steam://friends/status/offline`. Frame pacing is DXVK config / the Metal renderer. None
  depends on TF2's binary layout.
* Metal pipeline cache (`~/Games/tf2/cache/tf2mt/pipelines-v1.bin`): keyed by an FNV-1a hash of each shader's bytecode
  + translator version. Changed shaders get new keys; old entries are never matched (only prewarmed when both shaders
  are alive). Stale data cannot be used, so no version bump is needed.
* DXVK state cache (`steamapps/shadercache/440/DXVK_state_cache/`): DXVK also keys entries by shader hash and skips
  ones that do not match. Steam manages that folder.
